A2A Platform 前后端分离、鉴权与人类客户端设计

目标是在没有完整用户系统的前提下，让后端可以独立上线，让本地或第三方前端安全接入，并为人类用户客户端预留清晰的协议边界。

1. 当前结论

构建开关

保留现有 Go build tag frontend，外层提供 WITH_FRONTEND 变量。后端-only 和嵌入版走同一套源码。

鉴权边界

CORS 只能限制浏览器跨域读取，不是服务端认证。公开后端不能依赖 Origin 判断调用者可信。

人类客户端

先做轻量客户端身份和能力令牌，不引入账号、密码、组织、角色等用户系统。

2. 前后端分离部署

构建模式

模式 命令 产物 适用场景
后端-only make build WITH_FRONTEND=0 Go 二进制内只包含占位页 线上只部署 API，本地或独立静态站点提供前端
嵌入前端 make build WITH_FRONTEND=1 Go 二进制包含 Vite dist 单文件部署、内网演示、小规模运维
Docker 后端-only docker build --build-arg WITH_FRONTEND=0 . Runtime image 只包含后端 云端 API 服务
Docker 嵌入版 docker build --build-arg WITH_FRONTEND=1 . Runtime image 包含嵌入前端 一体化部署

本地前端连接线上后端

cd web/admin
VITE_DEV_API_PROXY=https://api.example.com npm run dev

# 或绕过 dev proxy，直接跨域请求远端 API
VITE_API_BASE_URL=https://api.example.com npm run dev

使用 VITE_DEV_API_PROXY 时，浏览器看到的是本地同源请求，Vite dev server 代转给线上后端。使用 VITE_API_BASE_URL 时，浏览器直接访问远端 API，后端必须把本地前端 origin 加入 cors_origins。

3. 鉴权与攻击面

核心判断

如果后端公网可访问，来历不明的前端、curl、脚本都可以尝试请求后端。CORS 只影响浏览器是否允许页面读取响应，挡不住非浏览器客户端。

当前接口分层

类别 示例 当前状态 风险
公开探活 /health 无认证 低，可能暴露服务存在与基础状态
发现与观测 /api/agents, /api/tasks, /api/traces 大多无认证 中，可能泄露 Agent、任务、上下文、trace 内容
交互调用 /agent/{name}, /api/contexts 无认证 高，可能消耗模型额度或触发工具调用
管理变更 POST /api/agents, POST /api/builtin-agents Admin token 中，token 一旦给不可信前端就等同泄露

建议的无用户系统权限模型

凭证 谁持有 能力 存储方式
admin_token 平台管理员 注册、删除、更新 Agent 与内建 Agent 后端配置或环境变量，不写进前端构建产物
client_token 可信人类客户端 列列表、创建会话、发送消息、读取自己的上下文 后端配置多个 token，可轮换，可命名
agent_secret Agent 或 Bridge Agent 自注册、心跳、回调、受限代理调用 Agent 配置，不交给浏览器

第一阶段可以只实现 client_token 的校验，不实现用户表。token 可以映射成一个逻辑客户端名，例如 local-dev-lijialun，用于审计与限制上下文可见范围。

CORS 策略

  • 生产环境不建议默认 *，应配置明确 origin，例如 https://admin.example.com 和 http://localhost:3001。
  • 允许本地调试时，推荐通过配置临时加入本地 origin，而不是放开所有来源。
  • 如果未来使用 Cookie，会增加 CSRF 风险。当前 token header 方案没有自动带凭证，攻击面更小。

4. 人类客户端设计

客户端目标

  • 人类用户打开客户端后，可以看到可用对象列表。
  • 对象可以是 Agent、Bridge、内建 Agent，也可以是未来的人类用户入口。
  • 点击对象后进入对话或交互页，显示对方类型、能力、上下文模式和在线状态。
  • 客户端不负责管理用户账号，只负责持有一个可撤销的客户端凭证。

5. 建议落地顺序

  1. 先落地构建开关和前端 API 基址配置，确保后端-only 可独立发布。
  2. 把生产 cors_origins 从默认 * 调整为显式白名单，并保留本地开发配置入口。
  3. 新增 client_tokens 配置和中间件，保护交互调用、上下文、任务、trace。
  4. 给 AgentCard 增加 x_actor_type 与 x_client_visible 扩展，客户端按这个字段渲染对象类型。
  5. 再实现人类客户端页面，不提前引入用户表和登录流程。
