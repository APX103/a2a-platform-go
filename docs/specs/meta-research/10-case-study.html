Question 对象

研究问题 设计一个通用深度研究架构，使其能产出可验证、可追溯、可迭代的新知识。
范围 科研协作、知识对象、验证协议、agent 编排、研究 UI、MVP 落地。
排除项 不承诺全自动科学发现；不在第一版做实体湿实验自动化；不替代 PI。
成功标准 一个真实研究问题能产生 Question→Hypothesis→Evidence→Reasoning→Claim→Review→Ledger 的完整链路。

生成三个假设分支

H1：对象工作台假设

深度研究的核心 UI 应是对象工作台，而不是聊天窗口。

branch-h1
H2：三层编排假设

Program / Branch / Activity 三层模型比单 FSM 更适合长期研究。

branch-h2
H3：验证优先假设

未验证 claim 不能入库，是系统和普通报告工具的根本边界。

branch-h3

H2 分支推进

状态 动作 产物
evidence Evidence Scout 收集 Temporal、LangGraph、科学工作流、OODA loop 的参考。 Publication、Evidence。
hypothesis Theorist 生成三层编排假设和可反驳预测。 Hypothesis H2。
verification_plan Experiment Designer 设计对比实验：单 FSM vs 三层模型。 VerificationPlan。
analysis Analyst 分析哪些任务需要并行 branch 和 durable wait。 Reasoning/Warrant。
review Critic 指出“概念合理但缺真实任务验证”。 Review: major_revision。
ledger_candidate Adjudicator 降级为 Promising Hypothesis，而非 Research Contribution。 Claim status: hypothesis_pool。

产生下一轮实验

因为 H2 没有被直接入库为贡献，系统生成下一轮研究任务，而不是强行写成结论。

实验 设计 成功指标
Workflow A/B 同一组研究任务分别用单 FSM 和三层模型执行。 阻塞处理时间、状态恢复准确率、对象链完整度。
UI Usability 研究员使用聊天 UI 与对象工作台完成同一任务。 claim 可追溯率、用户负担、错误定位时间。
Critic Isolation 比较普通自评 critic 与隔离 red-team critic。 有效 objection 命中率、下游 claim 修订率。

最终报告如何生成

报告不是凭空写出来，而是从对象网络投影出来。每段结论都能回链到 claim、reasoning、evidence 和 review。 

# 报告章节投影
1. 研究问题
   from Question
2. 候选假设
   from Hypothesis branches
3. 关键证据
   from Evidence grouped by claim
4. 推理链
   from Reasoning/Warrant
5. 验证状态
   from Claim.verification and Review
6. 已接受知识
   from Ledger accepted claims
7. 未解决问题
   from objections, blockers, low-confidence dimensions
8. 下一轮研究计划
   from VerificationPlan and spawned branches

这个案例暴露出的真实判断

好的研究系统不会急着把所有聪明想法都包装成结论。它应该有能力说：“这很有潜力，但当前只能是 V2 的组织内方法假设；要成为研究贡献，还需要真实任务验证和独立审查。”

这就是元研究系统和普通报告生成器的分界线：它不只是生成“看上去完整”的答案，而是持续管理答案的不确定性、验证计划和后续迭代。
