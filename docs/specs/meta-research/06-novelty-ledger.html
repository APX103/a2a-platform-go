Chapter 06 · Novelty Ledger

新颖性与入库：什么算新知识，什么只是重新发现

本章把“新知识”从一句主观评价拆成多维决策：组织内是否新、领域内是否新、是否可验证、是否严谨、是否重要、是否能产生后续研究。

核心问题

“新”不是一个单一属性。对一个实验室来说新，对全球领域可能早已常识；理论上新但不可验证，不能直接成为知识；非常严谨但没有意义，也不应占据高优先级。系统需要把这些状态拆开，而不是平均成一个 novelty_score。

四维入库空间

维度 问题 低分含义 高分含义
Novelty 它相对哪个知识范围是新的？ 只是复述或 rediscovery。 组织、领域或全球范围有新增。
Verifiability 它能被检查、反驳、复现吗？ 想法漂亮但无法测试。 证据、反例条件、验证计划完整。
Rigor 证据设计和推理是否可靠？ 证据弱、依赖同源、推理跳跃。 设计强、审查充分、替代解释被处理。
Significance 它是否值得进入长期知识账本？ 即使成立也影响很小。 改变决策、理论、方法或后续研究路线。

Novelty Scope

新颖性必须声明参照范围。否则系统会把“我们不知道”误判为“世界上没有人知道”。

Scope 含义 需要的检查
personal 对个人新。 只适合学习记录，不进入研究贡献。
organization 对本团队或机构新。 检查内部 knowledge base 和历史项目。
community 对某个子领域或实践社区新。 检查领域文献、标准、开源项目和专家审查。
global 对公开知识总体新。 必须有外部检索、文献对标和 novelty review。

新颖性类型

Empirical Novelty

发现新的事实、数据规律或观测结果。

Causal Novelty

提出新的因果关系或机制解释。

Method Novelty

提出新的方法、流程、工具或实验设计。

Conceptual Novelty

提出新的概念划分、框架或理论语言。

Combinatorial Novelty

把常规知识以非典型方式组合，产生新解释或新路线。

Disruptive Novelty

使旧 claim、方法或研究路线被替代、降级或重构。

Claim Ledger 决策

状态 条件 处理
Background Knowledge 可验证、严谨，但新颖性低。 入背景库，供后续研究引用。
Promising Hypothesis 新颖性高，但验证和严谨性不足。 进入假设池，生成验证计划，不可作为知识。
Research Contribution 新颖性、可验证性、严谨性、意义都过门槛。 进入 Claim Ledger，绑定版本、review 和复审触发器。
Operational Rule 全局新颖性可能不高，但对组织决策高价值。 进入组织知识库，标注 scope=organization。
Rejected / Retired 被反例推翻、意义不足或成本不可接受。 保留失败知识，防止重复踩坑。

条件化聚合，不做统一平均

不同 claim 类型需要不同门槛。统一权重平均会掩盖严重问题：因果 claim 如果 causal rigor 低，不能靠写作漂亮或意义重大补回来。 

{
  "admission_policy": {
    "causal_claim": {
      "required": {
        "verifiability": 0.70,
        "rigor": 0.70,
        "alternative_explanations_handled": true
      },
      "novelty_scope_min": "community"
    },
    "method_claim": {
      "required": {
        "method_novelty": 0.65,
        "reproducible_materials": true,
        "benchmark_or_case": true
      }
    },
    "conceptual_claim": {
      "required": {
        "conceptual_clarity": 0.75,
        "compression_or_unification": 0.60,
        "counterexamples_listed": true
      }
    }
  }
}

生产性新颖性

生产性新颖性本质上是延迟指标：一个新想法是否真正 productive，要看它后来是否产生可检验预测、新方法、新分支或跨项目复用。入库时只能用近端启发式，后续再更新。

  • 是否生成至少两个可检验预测。
  • 是否能拆分成多个后续研究问题。
  • 是否能压缩已有多个零散解释。
  • 是否能改变实验设计或产品决策。
  • 是否在后续项目中被引用、复用或反驳。
