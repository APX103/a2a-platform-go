Chapter 08 · Data Protocol

数据与协议：让研究对象、状态转移和审批都可执行

本章不是完整数据库设计，而是给出元研究系统的关键 schema 和事件协议。目标是保证前端、agent、后端和知识账本对“研究对象”有同一套语言。

协议原则

  • 对象创建、状态转移、审批和工具执行都必须产生事件。
  • 所有对象都带 provenance envelope。
  • 自然语言输出如果影响知识状态，必须落到结构化对象。
  • schema 校验只负责 hard gate，rubric 和人类判断作为独立 review。
  • 长周期动作必须有 durable wait 和 resume token。

数据完整性规则

规则 校验方式 失败处理
Claim 必须有 Reasoning hard gate 阻止进入 review 或 ledger_candidate。
Evidence 必须有 source schema 只能保存为 note，不能支持 claim。
V3-i 必须有独立复现 Activity policy gate 拒绝升级并创建 Curator task。
审批决定必须留痕 event log 没有事件则状态转移无效。
反例命中要传播 dependency graph 标记 downstream claim 为 needs_review。
