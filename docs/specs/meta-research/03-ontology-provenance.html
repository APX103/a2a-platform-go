Chapter 03 · Ontology

本体与溯源：把研究从文本变成可计算对象网络

本章定义研究系统的一阶对象。核心改动是把 Reasoning / Warrant 从 claim 的字段提升为对象，并为所有对象增加 provenance envelope，使系统能够回答“谁在什么活动中，用什么材料，生成了哪个结论”。

为什么需要本体

如果研究结果只存在于报告段落里，系统无法做复审、无法做反例传播、无法判断证据独立性，也无法跨项目复用。对象模型的目的不是把文档复杂化，而是让研究中的关键事实能被检索、验证、链接和更新。

一个合格的研究对象至少要能回答：它是什么、来自哪里、由谁生成、通过什么活动生成、依赖哪些对象、支持或反驳哪些 claim、当前验证状态是什么。

核心对象

对象 含义 关键字段 关系
ResearchProgram 长期研究单元，包含范围、目标、PI 和知识账本。 scope, exclusions, pi, approval_policy, ledger_id hasBranch, hasClaim, governedBy
Question 可研究的问题，定义范围和成功标准。 prompt, scope, assumptions, success_criteria spawnsHypothesis, refinesQuestion
Hypothesis 可检验的候选解释或方案。 statement, predictions, falsification_conditions answersQuestion, testedBy, competesWith
Evidence 支持或反驳 claim 的资料、数据、观察、实验结果。 source, design_level, extraction, reliability, independence_group supports, contradicts, derivedFrom
Reasoning / Warrant 连接 Evidence 与 Claim 的推理对象。 reasoning_type, premises, inference, assumptions, known_weaknesses usesEvidence, warrantsClaim, challengedByReview
Claim 可被验证、审查、入库或撤回的知识声明。 statement, scope, verification_level, confidence, novelty, status warrantedBy, reviewedBy, supersedes
Review 对 claim、evidence 或 reasoning 的审查。 reviewer, verdict, objections, required_changes reviews, raisesCounterEvidence
Activity 一次检索、分析、实验、审查或审批行为。 activity_type, inputs, outputs, tool, parameters, logs used, generated, attributedTo

Reasoning 必须对象化

原方案中 claim 可能包含一个 reasoning 字段，但这不够。字段不能被独立审查、版本化、引用或反驳。把 Reasoning 对象化后，一个 claim 的薄弱点可以被准确定位：是 evidence 不可靠，还是推理跳跃，还是 scope 写得过宽。 

{
  "id": "warrant-9f2",
  "type": "Reasoning",
  "reasoning_type": "causal_inference",
  "premises": [
    "benchmark A 中策略 X 在三类任务上提升成功率",
    "失败样本集中于上下文切换阶段",
    "策略 X 显式维护 branch state"
  ],
  "inference": "branch state 可能降低上下文切换损失，从而提升成功率",
  "assumptions": [
    "benchmark A 的任务分布代表目标使用场景",
    "成功率提升不是由 token budget 增加导致"
  ],
  "known_weaknesses": [
    "未完成 token budget 对照",
    "缺少外部任务集复现"
  ],
  "supports_claim_id": "claim-31",
  "uses_evidence_ids": ["ev-12", "ev-13", "ev-19"]
}

Provenance Envelope

每个对象都带统一溯源包，借鉴 W3C PROV 的 Entity / Activity / Agent 思路。这样系统能做责任追踪、复审传播和证据独立性判断。 

{
  "provenance": {
    "entity_id": "claim-31",
    "was_generated_by": "activity-analysis-77",
    "was_attributed_to": ["agent-statistician", "human-pi-001"],
    "was_derived_from": ["evidence-12", "evidence-13", "warrant-9f2"],
    "generated_at": "2026-05-23T11:40:00+08:00",
    "version": 3,
    "previous_version": "claim-31:v2",
    "license_or_access": "internal",
    "audit_log": ["event-901", "event-944"]
  }
}

外部知识对象

文献、数据集、方法、工具和概念必须是一阶对象。否则系统只能“引用一段文本”，无法表达文献之间的冲突、数据集复用、方法适用边界或概念同义关系。

Publication

论文、报告、网页、专利、标准。字段包括 DOI/URL、作者、日期、撤稿状态、引用链。

Dataset

数据集、实验日志、标注集。字段包括采样、版本、授权、缺失值、schema、可访问性。

Method

实验方法、分析方法、评估方法。字段包括适用条件、失败条件、参数和已知偏差。

AnalysisWorkflow

可执行分析流程。字段包括代码版本、环境、输入、输出、随机种子和运行日志。

Concept

术语、概念、分类。支持 SKOS 式 broader/narrower/related 和同义词。

Artifact

报告、图表、代码、实验材料。报告只是对象网络的一种投影，不是唯一真相。

关系类型

关系 语义 例子
supports / contradicts 证据支持或反驳某 claim。 Evidence A contradicts Claim B。
warrants Reasoning 将证据和 claim 连接起来。 Warrant C warrants Claim B using Evidence A。
derivedFrom 对象由另一个对象派生。 Analysis result derivedFrom Dataset V2。
replicates / failsToReplicate 复现关系。 Experiment E replicates Experiment D。
supersedes / narrows / generalizes claim 之间的版本和范围关系。 Claim V3 narrows Claim V2 after counter-evidence。
dependsOn 知识依赖关系，用于反例传播。 Claim B dependsOn Claim A。

对象入库最低要求

  • 每个 Claim 必须有至少一个 Reasoning 对象；不能只有 evidence 列表。
  • 每个 Evidence 必须有来源、设计等级、提取方式和独立性分组。
  • 每个 Activity 必须记录输入、输出、参数和执行者。
  • 每个 Review 必须有 verdict，不能只是自然语言评论。
  • 每个对象必须有 persistent id，跨项目复用时保留全局引用。
