Chapter 02 · Epistemology

认识论与验证：什么东西能从“想法”升级为“知识”

本章定义验证等级、证据设计、证伪条件和置信度更新。系统不负责宣布绝对真理，而是负责让每个知识声明的来源、边界、反例、复现状态和不确定性透明可审计。

基本立场

系统采用“可证伪的贝叶斯实用主义”：每个 claim 必须说明什么情况会削弱或推翻它，同时允许系统用新证据更新置信度。Popper 负责边界，Bayes 负责更新，审查记录负责责任。

这避免了原方案中的张力：confidence 不是“理论被证明为真”的分数，而是“在当前证据、设计强度和适用范围下的后验信念状态”。

验证等级 V0-V5

等级 名称 准入条件 不得自动化的部分
V0 Unverified Note 只是观察、想法、摘要或候选问题；可无正式证据。 不能进入知识库，只能进入研究草稿区。
V1 Source-grounded Claim 至少绑定一个来源或内部数据片段；能回答“从哪里来”。 不能推断为“成立”，只能说明有来源支持。
V2 Reviewed Claim 通过 Critic 或人类 reviewer 审查；记录主要反例、边界和不确定性。 严肃 claim 的 V1→V2 应有人类或隔离 critic gate。
V3-r Reproducible in Principle 材料、数据、代码、参数、环境和步骤足够，让独立方有机会复现。 不能声称已经被独立复现。
V3-i Independently Replicated 至少一个独立团队或隔离执行环境成功复现核心结果。 系统不能用同一 agent 自我复现来提升到 V3-i。
V4 Robustly Validated 多方法、多数据或多场景验证；主要替代解释被处理。 高影响 claim 需要 PI gate 或领域专家 gate。
V5 Operational Knowledge 被多个项目稳定复用，带有更新、撤回和版本治理机制。 不能由单次研究直接产生，必须经过时间和复用检验。

证据设计等级是正交轴

V 等级描述“这个 claim 被处理到了什么验证状态”，但不描述证据本身的研究设计强度。一个 V4 的观察性结论仍可能比一个 V2 的强实验结论更弱。因此系统需要同时记录 EvidenceDesignLevel。

等级 设计类型 适用说明
D0 Expert Note / Anecdote 专家意见、经验观察、非系统记录。适合生成假设，不适合强 claim。
D1 Documented Observation 有来源、有记录，但缺少控制和系统采样。
D2 Structured Dataset / Benchmark 有明确数据结构、采样和指标，可重复分析。
D3 Controlled Experiment 有对照、干预、预设指标，能支持因果或机制判断。
D4 Replication / Multi-site 独立环境、多点复现或跨数据集验证。
D5 Systematic Review / Meta-analysis 系统综述、元分析或跨研究纲领综合。

置信度向量

单一 confidence 分数不够。一个 claim 可能“在当前数据内很可信”，但“外推到其他场景很不可信”；也可能“理论上合理”，但“独立复现概率很低”。因此 confidence 必须是多维对象。 

{
  "confidence": {
    "truth_interval": [0.62, 0.78],
    "replicability": 0.70,
    "generalization": 0.45,
    "mechanistic_plausibility": 0.66,
    "evidence_independence": 0.52,
    "last_updated_at": "2026-05-23T10:20:00+08:00",
    "update_log": [
      {
        "event_id": "review-17",
        "delta": { "truth_interval": [-0.05, -0.02], "generalization": -0.12 },
        "reason": "critic found dataset comes from same upstream source"
      }
    ]
  }
}

证伪条件必须可执行

“如果有反例就推翻”不是证伪条件。合格的 falsification condition 必须写清条件、观察、阈值、测试状态和是否发生临时补丁。 

{
  "falsification_conditions": [
    {
      "condition": "在同一任务分布下，新编排策略的成功率低于基线 5% 以上",
      "measurement": "success_rate_delta",
      "threshold": -0.05,
      "test_protocol_id": "vp-042",
      "risk_level": "high",
      "tested": false,
      "outcome": "pending",
      "ad_hoc_rescue": null
    }
  ]
}
系统需要记录 ad hoc rescue。一个 claim 被反例击中后，如果研究者通过不断缩小范围来保住结论，应当降低 generalization，并触发 reviewer 复审。

知识升级规则

升级 硬门槛 软判断 审批
V0 → V1 至少一个 Evidence 或 Publication 引用。 来源是否相关、是否过时。 自动或 Staff Officer。
V1 → V2 至少一个 Review；反例条件完整。 reasoning 是否充分，边界是否明确。 Critic 或 PI。
V2 → V3-r 复现材料齐全，环境和参数记录完整。 材料是否足够让外部人理解。 Reproducibility Curator。
V3-r → V3-i 独立执行成功，有日志和差异说明。 独立性是否充分，复现是否覆盖核心结果。 Adjudicator 或 PI。
V3-i → V4/V5 多方法/多场景/跨项目复用证据。 是否仍有重大未处理替代解释。 PI 或委员会。

失败模式

  • 来源堆叠假象：多条证据来自同一上游来源，不能当作独立证据叠加。
  • 指标漂移：研究中途改变成功指标，但没有记录 preregistration 变更。
  • 复现误判：同一 agent、同一上下文、同一工具环境重复运行，被误标为独立复现。
  • 概念外推：claim 在小范围成立，却被写成普遍规律。
  • 置信度冻结：新证据出现后没有触发 update log 和 downstream claim 复审。
