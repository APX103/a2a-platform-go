Chapter 04 · Orchestration

编排与状态机：从单一循环升级为多分支持久化研究

真实科研不是一个 agent 在 collect-context 和 write-report 之间循环，而是多个假设分支同时推进、等待审批、等待实验、被反例打断、合并或废弃。本章定义 Program / Branch / Activity 三层编排。

为什么单 FSM 会坏

如果一个 Research Program 只有一个 current_state，就无法表达“假设 A 正在跑实验，假设 B 等待 PI 审批，假设 C 被反例打回，假设 D 正在整理证据”。这不是实现细节，而是研究语义错误。

单 FSM 的最大风险是把科研伪装成线性流程。它会诱导系统追求“下一步是什么”，而不是追问“哪个分支的什么不确定性最值得推进”。

三层编排模型

层 职责 状态 持久化要求
Program Orchestrator 管理长期目标、范围、资源、PI gate、知识账本和 branch 集合。 active, paused, under_review, archived 必须长期存在，支持跨月恢复。
Hypothesis Branch FSM 管理单个假设的认知状态和下一步策略。 scoping, evidence, hypothesis, verification_plan, experiment, analysis, review, ledger_candidate 每次转移都记录 event 和 gate。
Activity DAG 执行检索、分析、实验、审查、审批等具体动作。 queued, running, waiting, succeeded, failed, cancelled 记录输入、输出、工具、日志和可复现材料。

Branch 状态定义

状态 目标 退出条件 常见下一步
scoping 收敛问题范围、排除项、成功标准。 scope、assumptions、success criteria 完整。 evidence
evidence 收集和结构化证据。 至少一个 Evidence，且记录来源和设计等级。 hypothesis, scoping
hypothesis 生成或修订可检验假设。 假设、预测、反例条件完整。 verification_plan, evidence
verification_plan 设计验证方式、成本、风险、成功指标。 hard gates、soft scores、human gates 清楚。 experiment, review, await_approval
experiment 执行实验、仿真、数据分析或外部验证。 Activity 完成，产出 Evidence 或 Failure。 analysis, await_external
analysis 解释结果，生成 Reasoning 和候选 Claim。 Reasoning 对象和不确定性记录完整。 review, evidence, experiment
review Critic、Adjudicator 或 PI 审查。 Review verdict 存在，阻塞项处理。 ledger_candidate, revise, await_pi
ledger_candidate 判断是否进入知识账本。 V 等级、novelty、confidence、scope 齐全。 accepted, rejected, paused

Loop Guard

研究允许循环，但不能无限自我消耗。Loop Guard 不是阻止探索，而是发现停滞、升级不确定性、请求人类决策。 

{
  "loop_guard": {
    "max_visits_per_state": 5,
    "max_total_transitions": 40,
    "stagnation_window": 3,
    "stagnation_metric": "no_new_evidence_or_confidence_delta",
    "required_escalation": "ask_adjudicator",
    "on_trigger": [
      "summarize_blocker",
      "list_decision_options",
      "pause_branch_until_decision"
    ]
  }
}

硬门槛、软评分、人类门禁

LLM 可以辅助判断，但不能拥有全部控制权。每个状态转移都分三类条件。

条件类型 含义 示例 由谁判断
hard_gates schema 可校验，不满足则阻塞。 Claim 必须绑定 Reasoning；Evidence 必须有 source。 系统
soft_scores rubric 判断，用于建议继续或升级。 hypothesis specificity >= 0.7。 Staff Officer + Critic
human_gates 涉及责任、成本、伦理或外部发布。 批准实体实验、V3-i 入库、外部公开。 PI / 委员会

Durable Wait

长流程研究一定会等待：等实验排期、等 PI 批准、等外部数据、等独立复现。等待必须是显式状态，而不是让 agent 卡在一个长任务里。

分支操作

spawn

从一个 Question、CounterEvidence 或 Review objection 生成新假设分支。

merge

多个分支收敛到同一 claim 或同一验证计划，保留各自 provenance。

fork

同一假设因方法、数据或范围差异拆成多个可比较分支。

pause

等待审批、实验或外部事件，保留 resume token。

retire

因反例、成本或低价值废弃分支，但保留失败知识。

escalate

分支陷入冲突或循环时升级给 Adjudicator 或 PI。
