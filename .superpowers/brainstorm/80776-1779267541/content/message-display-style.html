消息展示设计

如何展示普通消息、Thinking 过程和工具调用

方案 A: 折叠式分组
U
帮我查询北京的天气
› Thinking (2 步) · 0.8s
[T1 0.2s] 需要调用天气 API 获取北京天气
[T2 0.6s] 解析返回结果并格式化
🔧 get_weather → 成功
{"city": "北京", "temp": 18, "condition": "晴"}
北京天气
当前气温: 18°C
天气状况: 晴 ☀️
A

折叠式分组

Thinking 和工具调用作为独立区块，可折叠/展开。Thinking 按时间分块标记。工具调用显示链式结果。

方案 B: 时间轴模式
U
帮我查询北京的天气
Thinking: 需要调用天气 API
get_weather → {"city":"北京","temp":18}
Thinking: 格式化结果
A
北京天气
18°C, 晴 ☀️

时间轴模式

所有事件沿时间线排列，清晰展示执行顺序。不同事件类型用不同颜色/图标标记。

方案 C: 内联式消息
A
💭 查询天气 API...
🔧 get_weather: {"city":"北京","temp":18}
北京天气
当前气温: 18°C
天气状况: 晴 ☀️

内联式消息

Thinking 和工具调用直接嵌入在 Agent 回复消息内部。简洁但可能难以区分复杂调用链。
